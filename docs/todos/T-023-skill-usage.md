# T-023 — 스킬 사용 집계와 표시

## 왜

대시보드는 "자주 쓴 툴"을 보여주지만 **어떤 스킬을 거쳐 왔는지**는 어디에도 없다. 툴 목록에
`Skill`이 한 줄로 뭉쳐 있을 뿐이라, `update-config`를 썼는지 `code-review`를 썼는지 알 수 없다.
스킬은 세션의 성격을 툴보다 잘 설명한다 — 무엇을 읽고 썼는지보다 어떤 작업을 했는지에 가깝다.

텔레메트리(T-021)에 `skill.name` 차원이 이미 있지만 그것은 **선택 기능**이다. 켜지 않은 사람도
보이는 곳, 즉 트랜스크립트에서 뽑아야 한다.

## 무엇을

1. `SessionSummary.skillUsage` — 이 세션이 쓴 스킬과 호출 횟수, 처음 쓴 시각.
2. `Stats.skills` — 스킬별 호출 수 **와** 그 스킬을 쓴 세션 수. 상위 12개.
3. 대시보드에 "자주 쓴 스킬" 카드.
4. 세션 카드와 세션 상세 헤더에 스킬 칩 — 어떤 세션이 어떤 스킬을 썼는지.

## 어떻게 세는가

트랜스크립트에는 "스킬을 몇 번 썼다"는 필드가 없다. 실측으로 확인한 두 신호를 합친다.

| 신호 | 어디에 | 뜻 |
| --- | --- | --- |
| `tool_use` `name: "Skill"`, `input.skill` | assistant 레코드 | 모델이 스킬을 호출했다 |
| `attributionSkill` | 스킬이 활성인 동안의 레코드 | 그 스킬 실행 중에 나온 결과 |

실측(`~/.claude/projects` 3개 세션):

```
(12, 'assistant', attr=None,            skilltool=['update-config'])   ← 호출 레코드
(22, 'assistant', attr='update-config', skilltool=[])                  ← 이후 레코드들
(23, 'assistant', attr='update-config', skilltool=[])
(28, 'assistant', attr='update-config', skilltool=[])
```

- **호출 레코드 자체에는 `attributionSkill`이 없다.** 그 뒤 레코드들에 붙는다.
- 붙는 구간은 **연속이 아니다.** 사이의 `tool_result` user 레코드에는 없다(21, 26-27번).

그래서 "마지막으로 본 스킬 이름"을 들고 다니며 **그와 다른 이름이 나올 때만** 새 호출로 센다.
`Skill` 툴 호출은 이름이 같아도 항상 한 번 더 센다.

### 한계 (문서에 남긴다)

같은 스킬을 슬래시 명령으로 **연달아** 부르면 한 번으로 접힌다. 툴 호출은 접히지 않는다.
정확한 실행 경계를 알 수 있는 필드가 트랜스크립트에 없으므로 휴리스틱으로 둔다 — 여기서
과하게 세는 것보다 덜 세는 편이 낫다. "스킬을 안 썼는데 썼다고 나온다"가 더 나쁜 오류다.

## 수용 기준

- [x] `GET /api/stats` 의 `skills` 가 `{name, count, sessions}` 를 호출 수 내림차순으로 준다.
- [x] `GET /api/sessions/:id` 의 `skillUsage` 가 처음 쓴 순서로 온다.
- [x] 스킬을 쓰지 않은 세션은 `skillUsage: []`, 화면에 칩 줄을 그리지 않는다.
- [x] `Skill` 툴 호출은 `toolUsage` 에도 그대로 남는다(집계를 옮기지 않고 더한다).
- [x] 대시보드 "자주 쓴 스킬" 카드가 호출 수와 세션 수를 함께 보여준다.
- [x] 세션 카드·상세 헤더에 스킬 칩. 2회 이상만 횟수를 붙인다.
- [x] 테스트: 툴+attribution 혼합, attribution 단독, 순서, 세션 수 집계.

## 하지 않는 것

- 텔레메트리 `skill.name` 과의 교차 검증. 켠 사람만 되는 비교라 화면의 신뢰도를 못 올린다.
- 스킬 이름으로 세션 목록 필터. `q` 검색 대상에 넣으려면 요약 필드를 늘려야 하고,
  스킬을 쓴 세션이 아직 적어 필터가 이득이 되는 시점이 아니다.
