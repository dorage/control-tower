# T-030 — 코드 문법 색칠과 설정 메뉴

- **ID** — T-030
- **우선순위** — P2
- **영역** — web-files
- **선행** — T-013, T-014, T-028
- **후행** — 없음

## 1. 목적

마크다운이 아닌 파일은 원문 탭에서 **색 없는 한 덩어리 텍스트**로 나온다. `.ts` 든 `.css` 든
로그든 똑같이 보여서, 코드를 읽으려면 결국 편집기로 옮겨 간다. 프로그래밍 언어로 보이는 파일은
색을 입혀 이 화면에서 읽히게 한다.

색 조합은 취향이 갈리고 밝고 어두운 화면 어디서 보느냐에 따라 읽히는 정도가 달라진다.
그래서 테마를 고를 수 있게 하고, 고를 자리로 **설정 메뉴**를 새로 만든다.

적용 범위는 두 곳이다 — 뷰어의 **원문 탭**과 마크다운 미리보기 안의 **코드 블록**.
편집 탭(`textarea`)은 건드리지 않는다(§2.4).

## 2. 전제와 판단

### 2.1 하이라이터를 직접 만든다

highlight.js·Prism·shiki 를 쓰지 않는다.

- **메인 번들에 들어가는 런타임 의존성은 `react`·`react-dom` 둘뿐이다.** CONVENTIONS §2 가 셋째로
  적어 둔 `@pug-frame/canvas`(T-029)는 sandbox iframe 전용으로 따로 묶여 메인 번들 밖에 있다.
  하이라이터는 그렇게 뺄 수 없다 — 파일을 여는 모든 화면이 쓰므로 메인 번들에 실린다.
  마크다운도 같은 이유로 자체 파서를 썼다(`lib/markdown.ts`).
- 셋 다 우리가 쓰는 것보다 훨씬 큰 것을 들여온다. highlight.js 는 공통 언어 묶음만 해도 이 앱의
  클라이언트 번들과 맞먹고, shiki 는 언어·테마 문법(TextMate grammar)을 JSON 으로 싣는다.
- 필요한 범위가 좁다. 서버의 `languageOf` 가 알아보는 확장자는 열두 개뿐이고, 목적은
  "읽기 편한 색"이지 "옳은 구문 트리"가 아니다.

**대가**: 색이 틀리는 자리가 있다. 정규식 리터럴과 나눗셈을 구분하지 않고, HTML 본문 안의 `=`,
셸의 `a-b` 같은 자리는 잘못 칠할 수 있다. 이것은 알고 받아들이는 비용이다.

**대신 하나는 절대 어기지 않는다**: 토큰 값을 이어 붙이면 입력과 글자 하나까지 같다.
색이 틀리는 것은 버그지만 글자가 사라지는 것은 사고다. 이 불변식을 언어별 표본으로 테스트한다.

되돌리기 쉽다. 하이라이터가 문제를 일으키면 `CodeBlock` 이 `plain` 한 덩어리를 돌려주게 하는
한 줄이면 원래 화면으로 돌아간다 — 모르는 언어가 이미 그 경로를 탄다.

### 2.2 HTML 문자열을 만들지 않는다

하이라이터는 HTML 이 아니라 토큰 배열을 돌려주고, `CodeBlock` 이 React 엘리먼트로 만든다.
마크다운 파서와 같은 규칙이다(CONVENTIONS §10) — `dangerouslySetInnerHTML` 을 쓰지 않으므로
sanitizer 가 필요 없고 XSS 위험이 구조적으로 없다. 남의 저장소 파일을 열어 보는 도구에서
이 성질을 포기할 이유가 없다.

### 2.3 테마는 CSS 변수, JS 는 이름만 옮긴다

`--code-bg` 부터 `--code-punct` 까지 열한 개 토큰을 두고, 테마는 그 값을 덮어쓰는 CSS 블록이다.
JS 가 하는 일은 고른 이름을 `document.documentElement` 의 `data-code-theme` 에 적는 것뿐이다.

- 색 계산을 JS 로 옮기면 CSS 토큰 규칙(CONVENTIONS §10)이 무너지고, 첫 렌더 전에 색이 없는
  한 프레임이 생긴다.
- 선택자를 `:root` 가 아니라 `[data-code-theme="..."]` 로 쓴다. 그래야 설정 화면의 미리보기
  카드마다 자기 테마를 걸어 **실제 색 그대로** 보여줄 수 있다.

**CONVENTIONS §10 의 "hex 는 `:root` 와 다크 미디어 블록 안에만" 규칙에 예외가 하나 생긴다.**
테마 팔레트는 화면 색이 아니라 사용자가 고르는 값이고, 값 자체가 그 테마의 정체라 토큰으로
바꿔 쓸 수 없다. 예외를 규칙 본문에 적어 남긴다.

기본값은 `auto` — 화면이 밝으면 밝은 색, 어두우면 어두운 색. 기존 화면과 이어지는 값이라
아무것도 고르지 않은 사람은 바뀐 것을 느끼지 않는다.

### 2.4 편집 탭은 색칠하지 않는다

`textarea` 는 안쪽에 엘리먼트를 둘 수 없다. 색을 넣으려면 색칠한 `div` 를 `textarea` 뒤에
픽셀 단위로 겹쳐 놓고 스크롤·줄바꿈·글꼴을 계속 맞춰야 하는데, 한글 조합(IME)과 실행 취소 스택을
지키는 지금의 편집기(T-013)를 그 위에 얹을 이유가 없다. 쓰기 허용 확장자는 기본이 `.md` 뿐이라
편집 대상이 코드도 아니다.

### 2.5 상한을 둔다

`HIGHLIGHT_MAX_CHARS = 120_000`. 넘으면 색칠하지 않고 한 덩어리로 돌려준다.
토큰 하나가 DOM 노드 하나라서 토큰 수가 그대로 비용이고, 뷰어가 멈추는 것보다 색이 없는 편이 낫다.
(실측은 §6.)

### 2.6 설정은 `localStorage` 에, URL 에는 두지 않는다

공유할 가치가 없는 개인 취향이다(CONVENTIONS §10 — 보기 방식과 같은 분류).
같은 브라우저의 다른 탭에는 `storage` 이벤트로 따라붙는다. 관제탑은 탭을 여러 개 열어 두고 쓴다.

## 4. 상세 명세

### 4.1 토큰

종류는 열 가지다 — `comment` `string` `number` `keyword` `type` `func` `property` `tag` `punct` `plain`.
CSS 클래스는 `tok tok--<종류>`, `plain` 은 span 없이 문자열로 나간다(본문의 절반이라 노드 수가 준다).

- `number` 는 숫자와 `true`/`false`/`null`/`this` 같은 원시 리터럴을 함께 받는다. 읽을 때 같은 무게다.
- `property` 는 객체 키·속성 이름·셸 변수·명령행 플래그를 함께 받는다.

### 4.2 스캐너

언어마다 **순서 있는 규칙 목록**을 둔다. 각 규칙은 sticky 정규식이고, 현재 위치에서 차례로 시도해
처음 맞는 것을 쓴다. 어느 규칙도 맞지 않으면 한 글자를 본문으로 흘리고 다음 위치로 간다 —
문법을 모르는 자리에서 멈추지 않기 위한 장치이자 §2.1 불변식의 근거다.

- 공백 규칙을 앞에 두어 대부분의 글자를 한 번에 건너뛴다(글자 단위 반복을 줄인다).
- **줄머리(`^`)에 걸린 규칙을 쓰는 문법(YAML·TOML)은 개행과 들여쓰기를 따로 먹는다.** `\s+` 로
  한 번에 삼키면 들여쓰기 뒤가 더 이상 줄머리가 아니라서 `^` 가 영영 맞지 않는다(구현 중 실제로 겪었다).
- 닫히지 않은 주석·문자열은 끝까지 먹는다. 파일이 잘려 있어도 뒤가 어긋나지 않는다.
- HTML 은 태그 전체를 한 번에 잡아 안쪽을 다시 쪼갠다. 속성값 안의 `>` 에 속지 않는다.
- 셸의 큰따옴표 문자열은 안쪽 변수를 살려서 쪼갠다. `"$NAME"` 을 통째로 칠하면 셸이 안 읽힌다.

### 4.3 언어

`javascript` `typescript` `json` `css` `html` `xml` `shell` `python` `yaml` `toml`.
서버의 `languageOf`(`fs.service.ts`)가 돌려주는 이름을 그대로 받고, 마크다운 코드 펜스의
손으로 적은 이름(`ts` `bash` `yml` `tsx` …)은 별칭표로 흡수한다.
모르는 언어와 `text`·`markdown` 은 색 없는 한 덩어리가 된다.

### 4.4 화면

`/settings` — 테마 카드 목록. 자동 / 밝은 테마 / 어두운 테마로 묶고, 카드마다 같은
타입스크립트 조각을 그 테마 색으로 미리 보여준다. 고르는 즉시 적용되고 저장 버튼이 없다
(되돌리기가 한 번의 클릭이라 명시적 저장이 필요 없다 — 편집기와 다른 이유다).

## 5. 수용 기준

- [x] 원문 탭에서 `.ts`·`.json`·`.css`·`.sh`·`.py`·`.yaml`·`.toml`·`.html` 이 색으로 구분된다
- [x] 마크다운 미리보기 안의 코드 블록도 같은 규칙으로 색칠된다
- [x] 모르는 확장자·바이너리·큰 파일은 예전과 같이 나오고 화면이 멈추지 않는다
- [x] 색칠 전후로 파일 내용이 한 글자도 변하지 않는다(테스트로 고정)
- [x] "설정" 메뉴가 생기고 테마를 고르면 즉시 반영되며 새로고침해도 남는다
- [x] 테마 카드가 각자 자기 색으로 보인다
- [x] `dangerouslySetInnerHTML` 을 쓰지 않는다
- [x] 런타임 의존성이 늘지 않는다(메인 번들에 들어가는 것은 여전히 react·react-dom 둘뿐)
- [x] 문서 4종(STRUCTURE·CONVENTIONS·README·TODO)을 갱신했다
